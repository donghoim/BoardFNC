# OneFabric

패션 AI 원단 B2B 쇼핑 플랫폼 — 0→1 신규 런칭

- **기간**: 2021.05 – 2023.01 (1년 9개월)
- **역할**: PM/기획 — 요구사항 정의, ERD 설계, SQL 작성·데이터 구조 검증, 정책·예외 케이스 정의, QA 시나리오 작성
- **구성**: PM/기획 3명 · 디자인 1명 · 개발 10명 · DB 2명 · QA 1명 (PM/기획 기준 본인 기여 30%)
- **Key Result**: 발주 프로세스 100% 디지털화, 발주 오류율 87%↓

## Why

섬유 원단 B2B 거래가 100% 오프라인(수기 장부, 전화 주문, 엑셀 재고)으로 이뤄지고 있었습니다. 발주 오류와 거래 이력을 추적할 방법이 없어 거래처 관리 비효율이 곧 매출 손실로 이어졌습니다.

## Approach

도메인 전문가 인터뷰로 요구사항을 정의하고, ERD를 직접 설계해 OneFabric·FabricMaster·OneRider 3개 서비스의 데이터 구조를 동시에 맞췄습니다. 발주 상태는 Enum 전이 6단계로 체계화하고, 실시간 재고 대신 트랜잭션 집계 방식을 선택했습니다.

## Key Decisions

| 대안 vs 대안 | 판단 기준 | 결정 | 결과 |
|---|---|---|---|
| 실시간 재고 집계 vs 트랜잭션 단위 집계 | 다건 동시 발주 시 실시간 집계는 정합성 오류 위험이 큼 | 트랜잭션 단위로 재고를 집계해 정합성을 확보하고, 집계 결과는 실시간 조회 가능하도록 구성 | 재고 정합성 오류 위험 감소 |
| EAV 구조 vs 카테고리별 고정 컬럼 | EAV는 쿼리 성능이 떨어지고 운영 편의성이 낮음 | 카테고리별 고정 컬럼 방식 채택(개발팀과 트레이드오프 협의) | 쿼리 속도·운영 편의성 확보 |
| 공급사·구매자 동일 화면 vs 권한별 뷰 분리 | 같은 데이터도 역할에 따라 다르게 노출돼야 함 | 뷰 레이어 완전 분리 | 역할별 정보 노출 범위 통제 가능 |
| OneFabric·ERP 동시 개발 vs 단계적 릴리스 | 동시 개발은 리스크가 큼 | OneFabric 안정화 후 ERP 단계적 연동 | 동시 개발 리스크 회피 |

## Output

**Product Impact**
- 발주 디지털화 100% (입점사 오프라인 주문 0건)
- 발주 오류율 87%↓ (수기 대비)
- 재고는 트랜잭션 단위 집계로 정합성을 확보하면서, 조회는 실시간으로 제공

**Business Scale**
- 누적 이용자 3만명, 누적 주문 84,000건, 누적 거래액 200억원 이상 달성 (2024 자료)
